# Контракт каталога SwimTab — версия 1

## Получение

`GET https://<домен-публикаций>/catalog.json`

Ответ: JSON в UTF-8, `schemaVersion: 1`. Авторизация не требуется.
nginx разрешает чтение с другого origin (`Access-Control-Allow-Origin: *`).
Запрос выполняется без cookies (`credentials: "omit"`). Ответ имеет
`Cache-Control: no-cache`: кеш допускается, но должен перепроверяться.

Главная Next.js со статическим экспортом получает каталог в браузере после
открытия страницы. Сборка главной не должна быть источником актуального списка.
Для открытой страницы допустимо повторять запрос раз в 60 секунд.
До первого успешного запуска сборщика endpoint может вернуть 404.
При ошибке загрузки главная сохраняет уже показанный список и сообщает об ошибке;
при первом запросе показывает возможность повторить загрузку.
Пустой массив `competitions` — корректный пустой каталог.

## Формат

Пример условный: путь не подтверждает существование такой публикации.

```json
{
  "schemaVersion": 1,
  "generatedAt": "2026-11-13T09:00:00Z",
  "competitions": [
    {
      "id": "2026/GNP/01",
      "year": 2026,
      "series": "GNP",
      "code": "01",
      "title": "Кубок Чемпионов Спринт 2025-2026",
      "url": "/2026/GNP/01/index.html",
      "sessionDates": ["2026-04-26"],
      "sourceUpdatedAtLocal": "2026-11-12T21:57:00"
    }
  ]
}
```

Все перечисленные поля обязательны; неизвестное время — `null`, неизвестные даты — `[]`.

| Поле | Тип и смысл |
| --- | --- |
| `schemaVersion` | Целое число, сейчас `1`. Неизвестную версию клиент не интерпретирует. |
| `generatedAt` | Дата-время UTC в ISO 8601. Время последнего изменения JSON, не heartbeat и не время соревнования. |
| `competitions` | Массив записей. Клиент группирует по `year`, затем `series`. |
| `id` | Уникальный в каталоге относительный путь `год/серия/код`, без URL-кодирования. При переименовании папки изменяется. |
| `year` | Число из имени годовой папки; не извлекается из названия или расписания. |
| `series` | Строка из имени папки серии с сохранением регистра. Справочника расшифровок нет. |
| `code` | Строка из имени папки соревнования. Ведущие нули сохраняются; числовой формат не обязателен. |
| `title` | Непустое название из HTML `<title>`, без конечного суффикса `- SPLASH Meet Manager ...`. |
| `url` | URL-кодированный путь от корня origin публикаций к `index.html`. Не относится автоматически к origin главной. |
| `sessionDates` | Уникальные даты `YYYY-MM-DD` по возрастанию из заголовков `td.title1`; ищется формат `DD.MM.YYYY`. Это найденные даты сессий, полнота календаря не гарантируется. |
| `sourceUpdatedAtLocal` | Локальное время из `#lastupdate`, `YYYY-MM-DDTHH:mm:ss`, либо `null`. Часовой пояс неизвестен; нельзя добавлять `Z` или автоматически трактовать как время браузера. |

Массив отсортирован по году по убыванию, затем по серии и коду
лексикографически по возрастанию. Клиент может менять порядок отображения.
Новые необязательные поля могут добавляться в версии 1; клиент игнорирует
неизвестные поля. Несовместимые изменения требуют новой версии.

Названия отображляются как текст, не через HTML-вставку.
Пример разрешения ссылки при отдельном домене главной:

```js
const catalogUrl = "https://files.example.com/catalog.json";
const response = await fetch(catalogUrl, {
  cache: "no-cache",
  credentials: "omit"
});
if (!response.ok) throw new Error("Не удалось загрузить каталог");
const catalog = await response.json();
if (catalog.schemaVersion !== 1) throw new Error("Неизвестная версия каталога");
// Для каждой записи:
// const href = new URL(entry.url, catalogUrl).href;
```

## Отбор публикаций и источники

Сборщик `catalog/collector.py` сканирует только
`data/<четыре цифры>/<серия>/<код>/index.html`.
Дополнительные префиксы, например `data/swimtime.online/2026/...`, сейчас
не поддерживаются. При такой реальной структуре нужно согласованно изменить
корень сканирования и публичный префикс URL.

Папки серии и соревнования с начальным `.` или `_`, а также символические
ссылки не сканируются. Архивные годы включаются на общих основаниях.
Лендинг в корне или в `data/swimtime.online` не включается.

Для новой записи необходимы:

- `meta[name="generator"]` со значением, содержащим `SPLASH Meet Manager`;
- непустой `<title>` после удаления суффикса;
- закрывающий тег `</html>`;
- файл размером не более 16 MiB, не изменявшийся последние 5 секунд;
- одинаковые размер и время изменения до и после чтения.

Поддерживается UTF-8 (по умолчанию) и явно объявленная в первых 8192 байтах
Windows-1251/CP1251. Комментарии о кодировке включённых фрагментов не являются
объявлением кодировки документа.

`alt`, картинки, PDF, ссылки на последний заплыв, город и бассейн не извлекаются
и не влияют на попадание в каталог. Статуса соревнования в контракте нет.
Расхождения оформления и расписания не проверяются. Даты и время могут
отсутствовать, быть нераспознанными или устаревшими в исходной публикации.

## Обновление и сохранение

Сканирование выполняется сразу после старта, затем раз в 60 секунд.
Интервал задаётся `CATALOG_INTERVAL_SECONDS` в Compose (минимум 5 секунд).
Из-за защиты от свежей записи новый HTML может попасть в следующий цикл.

Последняя успешная запись сохраняется, если HTML недописан, не распознан,
не читается либо временно отсутствует. Это не гарантия полной транзакционности
FTP: для неё публикатор должен загружать временный файл и переименовывать его
после завершения. PDF и другие зависимости HTML сборщик не проверяет.

Запись удаляется после удаления всей папки соревнования. Удаление только
`index.html` не удаляет запись. Для переименования: новая папка должна получить
валидный HTML, старая — быть удалена; иначе обе записи могут остаться в каталоге.
При общей ошибке обхода сохраняется прежний каталог.

JSON записывается только при изменении записей, через временный файл и атомарную
замену. Последнее состояние хранится в Docker volume `catalog-data` и читается
после перезапуска. `docker compose down` сохраняет volume; удаление volume
стирает сохранённые записи, после чего каталог строится заново из HTML.
Это текущее состояние каталога, а не история всех редакций.

## Развёртывание

Добавлены сервис `catalog`, volume `catalog-data` и точный nginx location
`/catalog.json`. Исходные FTP-файлы сборщик монтирует только для чтения.
JSON находится вне FTP-корня: обычная публикация не перезапишет его.
Сервису сборщика не нужен сетевой доступ.

После получения изменений на сервере:

```sh
docker compose up -d --build catalog http
docker compose exec http nginx -s reload
```

Reload нужен, чтобы работающий nginx гарантированно перечитал изменённый
конфигурационный файл. Главную и программу SPLASH эти команды не развёртывают.

Код предназначен для текущей схемы nginx, где корень URL соответствует `data`.
Фактический домен задаётся существующим `HTTP_HOST`; секреты в контракт не входят.
